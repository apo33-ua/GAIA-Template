# Personal Expense Management — Implementation Tickets

## Feature Overview

This document contains implementation tickets for the **Personal Expense Management** feature, broken down by user story. Each story is implemented using the **Thin Vertical Slice** pattern (DB → BE → FE), ensuring end-to-end delivery of value.

**Feature Scope:**
- Transaction management (income/expense CRUD)
- Automatic expense categorization
- Visual analytics (pie/bar charts)
- Budget management with threshold alerts
- Report export (CSV, PDF)

**Global Dependencies:**
- Authentication system (JWT-based)
- PostgreSQL database
- FastAPI backend (Python 3.11+, SQLAlchemy, Alembic)
- Frontend SPA (React/Vue + TypeScript, Vite, TanStack Query, Tailwind CSS)
- Chart library (Chart.js or Recharts)
- PDF generation library (jsPDF or backend-based)

### Tickets for PEM-USER-001

#### 1. - [x] **PEM-USER-001-DB-T01 — Create Transactions and Categories Tables** (2026-02-03)

- **Type:** DB
- **Description:** Create database schema for storing transactions and expense categories. Supports Scenarios 1, 2, 7.
- **Scope:**
  - **Included:**
    - `transactions` table with columns: `id`, `user_id`, `type` (income/expense), `amount`, `date`, `category_id`, `description`, `created_at`, `updated_at`
    - `categories` table with columns: `id`, `name`, `type` (expense/income)
    - Foreign key constraint: `transactions.category_id` → `categories.id`
    - Foreign key constraint: `transactions.user_id` → `users.id` (assumes users table exists)
    - Index on `(user_id, date)` for query performance
    - Index on `(user_id, category_id)` for aggregations
    - Check constraint: `amount > 0`
    - Check constraint: `type IN ('income', 'expense')`
  - **Excluded:**
    - Recurring transactions
    - Multi-currency support
    - Transaction attachments
- **Dependencies:** None (assumes `users` table exists from auth module)
- **Deliverables:**
  - Alembic migration file: `create_transactions_and_categories.py`
  - ERD update documenting new tables and relationships
  - Seed data for predefined categories: Food, Transportation, Entertainment, Utilities, Health, Other
  - PII security note: `amount` and `description` are sensitive; ensure encryption at rest
  - Migration rollback script tested

- **Type:** BE
- **Description:** Implement GET `/api/budgets/status` endpoint to return budget usage with alert thresholds. Supports Scenarios 1, 2, 3, 4.
- **Scope:**
  - **Included:**
    - GET `/api/budgets/status` endpoint

      - Authorization: Filter by `user_id` from JWT
      - Observability: Log analytics event when threshold crossed (WARN level for 80%, ERROR level for 100%)
    - Use case: `GetBudgetStatusUseCase`

#### 2. - [ ] **PEM-USER-008-BE-T02 — Implement Categorization Suggestion Endpoint**

- **Type:** BE
- **Description:** Implement POST `/api/categorization/suggest` endpoint to suggest category based on description. Supports Scenarios 1, 2, 3, 4, 5, 6.
- **Scope:**
  - **Included:**
    - POST `/api/categorization/suggest` endpoint
      - Request DTO: `CategorizationRequest` with field: `description`
      - Response DTO: `CategorizationResponse` with field: `suggested_category_id`
      - Logic:
        - Tokenize description (split by whitespace, lowercase)
        - Match tokens against categorization_rules.keyword (case-insensitive)
        - Return category_id of first matching rule (ordered by priority)
        - Default to "Other" category if no match found
      - Performance: < 50ms response time
      - Privacy: Do NOT log `description` in application logs, only log `suggested_category_id`
    - Use case: `SuggestCategorizationUseCase`
    - No authorization required (stateless suggestion, no user data involved)
  - **Excluded:**
    - Learning from user overrides (future enhancement)
    - Multi-language support
- **Dependencies:** PEM-USER-008-DB-T01
- **Deliverables:**
  - Router: `backend/app/presentation/routers/categorization.py`
  - DTOs: `CategorizationRequest`, `CategorizationResponse`
  - Use case: `backend/app/application/use_cases/suggest_categorization.py`
  - Unit tests for use case (keyword matching, case-insensitivity, default to Other)
  - Integration tests for endpoint (happy path, no match, performance)
